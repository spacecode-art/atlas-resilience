# Atlas Resilience v1.0.0

Phase 5 of the Atlas DevSecOps path: failure experiments on a local 3-zone
kind cluster, with measured recovery and a ledger check that every sale
the client was told about is a database row.

## What is shown
- SC-01 to SC-04 run with RTO measured; SC-03 RTO was 90 s in all three runs.
- Retry safety (H4): 12 of 12 lost responses recovered by replaying the same
  request ID, one row each (run sc03d).
- Volume-loss drill: 187 s of exposure, 150 sales (run rpo2). A backup of the
  `public` schema alone is not a full recovery.
- SC-04 expired certificate (run demo2): 1,950 sent, 1,609 validated sales,
  1,609 database rows, 0 missing, 0 duplicates, 0 lost responses.
- Demo video: see the README, "Demo Video".

## What is not shown
- Results are single local runs. No general or production claim.
- The sale-detection gap (F-01) is open: the failure did not raise an alert.
- There are no automated backups, and no retry-capable client.
- sc03b and sc03c lost responses were not replayable.
- Future Roadmap in the README lists the follow-up work.
