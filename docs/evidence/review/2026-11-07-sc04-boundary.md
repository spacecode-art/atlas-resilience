# SC-04 boundary validation — 2026-11-07

This record covers the disposable TLS boundary and reload fixture only. It is
not a certificate-expiry experiment and contains no live RTO/RPO claim.

## Checks

```text
node --test tests/sc04-tls.test.mjs                  PASS
shellcheck scripts/sc04-certificate-expiry.sh        PASS
bash -n scripts/sc04-certificate-expiry.sh           PASS
```

The fixture started `tls/sc04-proxy.mjs` over a local HTTP upstream, completed
a trusted HTTPS request, replaced the leaf certificate, sent `SIGHUP`, completed
another request and confirmed the child process ID was unchanged. The test CA
and keys were generated under a temporary directory and removed after the test.

## Boundary and safety properties

- The proxy image is the already loaded local `tawira:chaos-local` image; the
  live runner records the image ID before injection.
- The CA is mounted only into the fresh load pod. The proxy receives only the
  leaf key and certificate through a disposable Secret.
- The expiry fault changes `notAfter` in the leaf presented during new TLS
  handshakes. It does not delete the Secret, stop the proxy, restart Tawira or
  change the local clock.
- Recovery installs the valid leaf and sends `SIGHUP`; the runner verifies the
  proxy pod has not restarted and a new trusted handshake succeeds.
