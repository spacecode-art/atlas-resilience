# SC-03 `sc03d`: replay of lost responses

**Date:** 2026-11-09
**Classification:** valid local DNSChaos run plus a separate, valid replay of its lost responses

## Fault run

`sc03d` repeated the SC-03 DNS fault: 1,950 requests at 5 RPS, 1,752 validated
sales, 186 clean failures and **12 lost responses** (sales recorded in the
database with no acknowledgement to the client). There were no duplicate tags,
unmatched rows or acknowledged-but-missing sales. Lost responses so far: 17
(`sc03b`), 25 (`sc03c`), 12 (`sc03d`). Sale-success recovery was **90 s**
(30 s resolution), the same as `sc03b` and `sc03c`.

## Replay

After recovery, `scripts/sc02-replay.mjs --replay-lost` resent each of the 12
lost requests with its original `requestId`, tag and product. The send times are
the `sent_ts` fields in `replay-lost.json`, over an hour after the fault.

| Result | Observation |
|---|---|
| Replayed | 12 |
| Returned the original sale ID | 12 |
| Ledger rows per tag after replay | 1 (re-exported to `ledger-after.json`) |
| New tags, duplicates, different sales | 0 |

H4 (retry/idempotency safety) is supported for these 12 requests: every sale
the client never heard about was recoverable by retrying with the same request
ID, without a second charge.

## Invalid first attempt (preserved)

The first replay used `TARGET_URL=http://127.0.0.1:3000`, which on this host is
Grafana. All 12 requests returned HTTP 404 HTML. No sale was touched, and the
"0 safety failures" in that attempt is meaningless. Files are kept as
`replay-lost.INVALID-grafana-404.json`, `ledger-after.INVALID.json` and
`verify-lost.INVALID.txt`. The replay tool now aborts on any non-200 response.

## Limits

- One local run. The lost responses of `sc03b` and `sc03c` cannot be replayed
  because those runs did not log `productId`.
- Same user, shop and branch, sequential replay, quantity 1. Idempotency scope
  across users or branches, and replay under concurrency during an outage,
  were not tested.
- The generator itself never retries. This shows that a retry would be safe,
  not that any client retries.
